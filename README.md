本地化源文件位于 `BlackFlowSpire/localization/<语言>/<范畴>.json`，语言目录为 `eng` 和 `zhs`。两种语言使用相同的八张表。

| 文件 | 文案 |
| --- | --- |
| `nodes.json` | 地图节点类型、标题和说明 |
| `stages.json` | 普通、紧急和 Boss 关卡的标题与说明 |
| `exploration.json` | 行动、移动、追猎、情报、区域入口和楼层出口 |
| `parts.json` | 部件、自然物、概念体及相关界面 |
| `shop.json` | 商店、商品和商人对话 |
| `secret_shop.json` | 隐藏商店 |
| `ui.json` | 模式入口、通用按钮、顶栏、队伍和速度 |
| `preview.json` | 开发地图预览 |

直接编辑 JSON，保持中英文的键和命名参数一致。仓库附带由 JSON 生成的 `preview_eng.translation` 和 `preview_zhs.translation`，供 Godot 编辑器预览。更新文案后，在本地重新生成对应的预览资源并随 JSON 提交。RitsuLib 将各范畴注册为 Mod 自己的本地化表，游戏通过原版 `LocString` 取词，缺少译文时回退到英文，切换语言时刷新。

节点详情统一从 `MAP.*.description` 读取，已完成节点不再被通用 UI 说明覆盖。通用战斗类别说明留空，实际战斗和 Boss 使用 `MAP.STAGE.*` 本地化键。不再保留已移除的 tips 文案。按用户当前范围，步行前往／无法抵达等 PNG 中的文字暂不处理。

行动力与前往 UI 迁移了用户本机提取的黑流树海素材。`ForestActionPoints.tscn` 显示原行动力圆底、实时剩余数字和步行脚印；`ForestMoveButton.tscn` 显示原消耗提示与步行／无法抵达图片。两个状态按可达性互斥，当前位置隐藏前往控件。`ForestMovementVfx.tscn` 将原圆形网格、UV、六层材质和时间采样运算迁移为 Godot CanvasItem Shader，按用户要求步行也使用同一套旋涡。原 Unity 业务动画代码不在提取结果中，动画时间与交互由 Mod 驱动；加工品切换暂未接入。

每个战斗和 Boss 节点在生成地图时固定原版遭遇、独立随机种子、实际敌人 ID、数量和站位，并写入 RitsuLib 地图存档。已揭露战斗可通过“敌方情报”打开原版弹窗框架，选择敌人查看原版怪物素材和数量；未揭露战斗禁止查看情报，Boss 始终可以查看。进入战斗从同一份种子恢复原版编成并核对，避免预览与实战不一致。旧地图会补全编成；已完成战斗优先采用原版楼层历史中的敌人记录。

BFS 搜索中途经过空节点、已完成的一次性节点或显式允许穿过的节点；其他遭遇只能作为终点。行动力足够支付整段路径时才允许出发，确认移动时重新检查规则；沿途逐格扣费、记录原版楼层历史、自动保存并累计揭露三步范围，中间房间不弹出地图。节点默认一次性：完成后停留原地仍保留内容，实际离开时才变为空白节点，同时清除战斗编成与详情来源；原版地图点类型同步清空，历史记录保留。`ForestNode.Repeatable` 可显式标记可重复节点，目前诡意行商与曲折密道为 `true`；诡意行商回访时重新进入商店。查看详情不改变位置、行动力或迷雾，描述仅使用可见图标分类，Boss 名称仍始终可见。

曲折密道使用原节点 ID `DOOR`，类型为传送、描述为“本地人的杰作。”。每幕有概率生成且最多一对，`ForestGenerationOptions.DoorPairChancePercent` 默认30，可设为0关闭或100保证在候选充足时生成。从普通事件或空白位置中选取两个相距较远的节点，不替换战斗、奖励、商店、起点与Boss；通过 `PairedNodeId` 双向配对并随地图保存。两端立即揭示、可重复，`CanPassThrough` 允许徒步路线越过尚未完成的密道；路过不触发选择，也不会完成节点。以密道为移动终点时，弹窗选择“穿越密道”或“留在此处”，只支付到入口的道路消耗；传送不扣行动力，目的地按侦察范围更新视野，视角移向落点，不会在另一端循环弹窗。密道选择保存为待处理节点，读档后继续选择；行动力归零时先处理密道，再触发追猎。规则实现见 `ForestPassageRules.cs`，生成配对见 `ForestPassageAssignments.cs`；详情的规则说明与“可重复／立即揭示”标签均读取中英本地化。

“居民”据点使用 `BATTLE_SAVAGE`，每幕按 `ResidentStrongholdChancePercent`（暂设30）概率从普通事件或空白位置生成一个；出现时，在沿实际道路5步内的原生空白节点上放置最多3个流窜“居民”，不足则少生成。居民立即揭示，以独立占领层保存，不改写原节点类型和固定遭遇；被占领节点无法穿过。每次确认前往后，居民沿相连道路随机移动一格，无合法位置则停留；步行进入密道后的传送或留在原地选择与该次前往合并结算一次。不会进入玩家所在节点、出口Boss、可重复节点、据点或完成节点产生的空白。驱逐单个居民会立即毁掉所在节点并变为空白；击败据点在正常奖励结算后驱逐全区域居民，解除其他节点占领并保留其原内容。专用战斗按用户要求留待补齐，当前禁用进入及敌方情报，不抽取替代战斗。未来编成入口和机制说明见 本地开发记录 `RESIDENT-NODES.md`。

羽瞰点使用 `LIGHT`，类型为视野。每幕暂按 `VantagePointChancePercent`（30%）概率从普通事件或空白位置生成一个，先于居民生成，因此居民初始仍只出现在原生空白，之后可以移动到羽瞰点上。出现时立即揭示自身及坐标距离4格内的节点，首次实际到达时扩大至12格并获得1行动力。范围采用四向网格的曼哈顿距离（横向差与纵向差相加），与道路是否连接或绕行无关；普通侦察仍按道路3步计算。未访问的羽瞰点不能当作中间节点直接越过，正常到达后直接回到地图；离开后按一次性规则变为空白，已经揭示的信息永久保留。`VantageActivated` 随地图保存，查看、读档或居民胜利结算不会重复领奖。居民占领不覆盖底层 `Light` 类型，因此首次到达被占领的羽瞰点也会先扩大视野并补回1行动力，再进入专用战斗；专用战斗目前仍待补齐。追猎预警和预计剩余行动力均计入到达奖励。

羽瞰点强化条件由 `ForestGenerationOptions.GameOfLifeSplitUnlocked` 与 `SecrecyLevel` 提供：只有分裂已点亮且保密等级≥3，出现／到达范围才使用12／24格。默认false／0。生命游戏与保密等级选择、解锁持久化尚未实现；这两个字段是供未来系统传入的独立条件，未接入原版进阶等级。规则入口为 `BlackFlowSpireCode/Map/Exploration/ForestVantageRules.cs`，生成入口为 `ForestVantageAssignments.cs`；中英文标题和描述保留原文，规则数值通过本地化参数传入。

每幕默认 20 点行动力，每条道路消耗 1 点。空节点直接通过；其他节点使用固定房间类型或专用地图交互，一次性节点离开后仅作为空房通行。战斗中从顶部查看地图只能查看，不能绕过当前战斗。行动力、当前位置、迷雾、节点内容、可重复标记、完成状态和追猎阶段均保存到 RitsuLib 局内数据。归零时先完成当前遭遇及奖励（包括回访的可重复节点），返回地图后强制播放追猎提示；空房在整段移动结束后触发。羽瞰点到达奖励先结算，再判断是否归零。确认“无路可逃”进入追猎详情，普通探索锁定，右下角切换红色出发状态。追猎专用战斗尚未接入，敌方情报和出发按钮暂时禁用，不代用随机原版敌人；可通过原版菜单保存退出。读档保留待提示或待出战阶段，不会重播已确认提示。已击败出口 Boss 时优先转幕。补给等其他扩展规则尚未实现。

## 已实现规则

黑流模式新开局共五层，配置集中于 `BlackFlowSpireCode/Map/Models/ForestFloorPlan.cs`。节点总数包含起点与终点；普通和紧急作战均按对应原版区域选关，保留已编写的独立关卡版本与数值。

第一层不生成曲折密道和羽瞰点，分别由该层的 `AllowPassages` 与 `AllowVantagePoints` 控制。层级开关优先于生成概率；第二至第五层继续按原概率生成。

| 层 | 节点总数 | 怪物来源 | 终点 |
| --- | ---: | --- | --- |
| 一 | 25 | 原一层 | 险路尽头 |
| 二 | 35 | 原一层 | 险路恶敌 |
| 三 | 45 | 原二层 | 险路尽头 |
| 四 | 49 | 原二层 | 险路恶敌 |
| 五 | 49 | 原三层 | 险路恶敌 |

`ForestCampaignService` 在黑流新局初始化房间之前建立五个独立区域实例；两层相同区域不共用房间队列，原版模式不变。第 1、3 层各有概率生成一个险路小径（默认 15%，最多一个），终点为立即揭示的险路尽头；第 2、4、5 层不生成这两类节点。两者均先打开原素材事件界面，由玩家选择是否换层。尽头只保留“说服同伴”和“离开黑池”，前者获得一个随机加工品后进入下一层，后者返回地图并保留出口。小径的奖励、行动力处理、素材与代码入口见 本地开发记录 `FLOOR-EXITS.md`。险路恶敌继续使用原版 Boss 图标和独立关卡文本，战斗奖励后换层；第五层按原版最终 Boss 流程结算。已有地图快照不重抽，不修改当前对局存档。

- 默认 9 × 9 坐标范围，按各层数量生成连通节点，包含中心起点与一个外围终点。未生成节点的坐标是地图空洞；空节点本身存在且可通行。
- 道路只连接上下左右相邻的节点，每条路均可双向经过。
- 先生成满足行动力预算的终点主路，再扩展连通支路；默认添加四条额外道路形成环路，有效候选不足时取可用数量。
- 终点位于外围，只有一条相邻道路，普通节点不会被安排在必须经过终点才能到达的位置。
- 起点固定为空节点。除起点和终点外，以 35:40:25 的权重分配为空、战斗、事件，先算配额，再洗牌。
- 以四、五层的 49 节点为例，特殊节点替换前的配额为：普通空节点 16 个、战斗节点 19 个、事件类节点 12 个，另加起点与终点。其他层按相同比例分配。若本层生成密道，会将其中两个普通事件或空节点替换为成对的密道。
- 战斗内部以 80:20 分配普通与紧急；事件内部以 60:20:20 分配事件、奖励、商店。采用最大余数法分配整数配额，49 节点时分别为普通战斗 15、紧急 4、事件 7、奖励 3、商店 2。
- 真实房间类型和战斗编成在生成时固定，不在查看地图或读取快照时重抽。普通与紧急关卡仅从该层对应的原版区域选取；事件与奖励沿用原版抽取和结算流程。
- 空节点直接显示；未揭示战斗统一为“未知的凶戾”，未揭示事件类统一为“未知的诡秘”。两组各自共用图标键与名称。
- 险路尽头与 Boss 始终显示真实信息，与 `Revealed` 标记无关。Boss 使用独立关卡文本与原版图标。
- 初始位置为中心起点，起点默认已完成。地图生成后立即揭露从起点沿道路 3 步内可达的真实节点类型；其他普通节点默认未完成。
- 揭露使用 BFS 计算最短道路步数，包含当前位置（0 步）和恰好第 3 步。没有道路连接的坐标相邻节点不能直接算作 1 步；空节点也按经过一条道路计 1 步，行动力消耗不影响这个距离。
- 位置更新后自动重新揭露 3 步范围，揭露结果永久累计，离开范围不重新遮蔽。空节点与终点始终可见。
- `CurrentNodeId` 和节点 `Revealed` 一起保存。旧快照缺少当前位置时按起点处理，缺少 `RevealRadius` 时默认 3 步；布局、配额和固定内容保持不变。
- 使用独立、版本化的 SHA-256/SplitMix64 随机流，不消耗原版战斗或奖励随机数。同种子、同幕索引、同配置生成相同地图。
- RitsuLib 局内存档保存完整节点、连线、真实类型和状态，不只保存随机种子。已存在的同幕快照优先复用，避免配置变动使已生成的地图重抽。

## 构建与导出

1. 安装 .NET 9 SDK、Godot 4.5.1 .NET 和对应的 Windows 导出模板。项目目标游戏 API 为 `0.111.0`。
2. 在仓库根目录创建 `dll/`，从游戏安装目录的 `data_sts2_windows_x86_64/` 复制 `sts2.dll`、`0Harmony.dll` 和 `GodotSharp.dll`。将完整的 RitsuLib `0.6.10` 包解压到 `dll/STS2-RitsuLib/`，保留目录结构，让 `RitsuLib.References.props` 位于该目录根部。在 `dll/` 中创建空的 `.gdignore` 文件。
3. 在 Godot 中导入根目录的 `project.godot`。在「项目 → 导出」选择 `BlackFlowSpire PCK`，执行「导出 PCK/ZIP」，保存为 `artifacts/mods/BlackFlowSpire/BlackFlowSpire.pck`。
4. 确认输出目录中有 `BlackFlowSpire.dll`、`BlackFlowSpire.pck` 和 `mod_manifest.json`。DLL 和清单由主工程的构建目标复制到该目录。可将这三个文件和 README 打包为供玩家下载的 ZIP。

可以在导出前检查依赖路径并单独编译 DLL。

```powershell
dotnet msbuild BlackFlowSpire.References.props -target:ValidateBlackFlowSpireDependencyReferences
dotnet build BlackFlowSpire.csproj -c ExportRelease -r win-x64
```

### 本地开发预览

以下命令适用于保留了本地 `tools/BlackFlowSpire.MapPreview/` 的开发工作区。也可用游戏内的 `bfs_map` 命令导出 SVG 预览。

独立生成其他种子，`--act` 是从 0 开始的幕索引：

```powershell
dotnet run --project tools/BlackFlowSpire.MapPreview -c Release -- --seed MySeed --act 1 --output artifacts/preview/MySeed
```

可通过 `--reveal-steps 3` 设置揭露范围；`--walk 49,50,59` 会从起点依次沿道路更新位置并揭露。例如默认 `BFS-DEMO` 种子可执行：

```powershell
dotnet run --project tools/BlackFlowSpire.MapPreview -c Release -- --seed BFS-DEMO --walk 49,50,59 --output artifacts/preview/walk
```

每一步必须到相邻且有道路连接的节点，否则报错。该工具只模拟位置与揭露，尚不结算房间或消耗行动力。`map.json` 中可查看节点 ID，SVG 标题栏显示当前位置，双圈标记当前位置。

可通过 `--options options.json` 覆盖生成配置，例如：

```json
{
  "Width": 9,
  "Height": 9,
  "NodeCount": 49,
  "InitialActionPoints": 20,
  "MoveCost": 1,
  "RevealRadius": 3,
  "MinimumBossDistance": 6,
  "ExtraConnections": 4,
  "EmptyWeight": 35,
  "CombatWeight": 40,
  "EventWeight": 25,
  "ElitePercent": 20,
  "RegularEventWeight": 60,
  "RewardWeight": 20,
  "ShopWeight": 20
}
```

宽高必须是 5–31 范围内的奇数。`NodeCount` 包含起点和终点；显式传入配置时覆盖该层的默认节点数，未传入则使用五层配置。无法同时满足外围位置、最小距离、节点数、行动力预算的配置会报错，不会无限重试。默认配比和数值是原型参数，可修改。

## 游戏内开发入口

目标游戏 API 为 `0.111.0`，依赖完整 RitsuLib `0.6.10`。将 `artifacts/mods/BlackFlowSpire/` 和 `dll/STS2-RitsuLib/` 分别复制为游戏的 `mods/BlackFlowSpire/` 与 `mods/STS2-RitsuLib/`，然后启用这两个 Mod。

早期原型的 `BFS` Mod ID 已改为 `BlackFlowSpire`。未迁移旧 ID 的局内存档槽；独立地图 JSON 格式保持兼容。安装新包时应停用旧 `BFS` 原型，避免重复注册 `bfs_map` 命令。已有同版本 RitsuLib 时无需再安装一份。

在已开启的游戏开发控制台执行：

```text
bfs_map
bfs_map MySeed 1
bfs_map run
bfs_map step 41
bfs_map check
bfs_map hunt-preview
```

- `bfs_map`：用默认种子生成独立预览。
- `bfs_map MySeed 1`：生成指定种子、第 2 幕的独立预览。
- `bfs_map run`：按当前单人跑局的种子与幕生成/复用 RitsuLib 局内快照，并导出预览；完整快照在游戏下次正常保存时写入。多人局暂不接受此命令。
- `bfs_map step <nodeId>`：仅在普通单人跑局的独立预览中更新位置和侦察，不进入房间或扣行动力。正式黑流树海对局会拒绝该命令，必须使用地图按钮移动，以保持行动力、房间与原版存档坐标一致。
- `bfs_map check`：在游戏运行时验证原版地图 JSON 保存/读取、双向道路和起点/Boss 实例引用。
- `bfs_map hunt-preview`：只读预览追猎入场，确认后查看追猎详情，用左上“关闭”退出。该预览不改变行动力、追猎阶段或存档；实际归零流程没有这个预览关闭按钮。

导出位置为 Godot `user://BlackFlowSpire/previews/`，命令执行结果会显示实际路径。重复导出同一幕会更新该幕的预览文件。`run`、`step` 和 `check` 是保留参数。

这些开发命令不切换玩法。正式玩法由模式选择入口启用：空节点与回访节点进入 `MapRoom`，事件类按固定内容选择原版事件、宝箱或商店，不使用原版问号节点的随机房间判定。

## 代码入口

- `BlackFlowSpireCode/Integration/ForestActMap.cs`：原版二维地图、节点和房间类型映射。
- `BlackFlowSpireCode/Integration/ForestRuntime.cs`：实际移动、房间切换与地图检查点。
- `BlackFlowSpireCode/Integration/ForestPatches.cs`：模式页入口、生成、查看地图及恢复存档补丁。
- `BlackFlowSpireCode/Ui/ForestMapUi.cs`：平面地图与可移动节点按钮。
- `BlackFlowSpireCode/Ui/ForestMapAssets.cs`：原版贴图、字体及当前压缩图集的裁剪/留白恢复。

- `BlackFlowSpireCode/Commands/BfsMapConsoleCmd.cs`：游戏内生成、导出与运行时检查命令。

根目录 Mod 工程显式编译 `BlackFlowSpireCode/**/*.cs`，生成单个 `BlackFlowSpire.dll`；参考源码、测试与工具不会混入 Mod。离线生成器工程复用 `BlackFlowSpireCode/Map/` 下同一份源码，测试和预览工具通过该工程引用地图逻辑。
